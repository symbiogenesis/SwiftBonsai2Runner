# Swift Bonsai 2 Runner v0.2.1

Experimental Windows ARM64 release for Snapdragon X and X2 laptops.

The portable single executable includes the native Rust chat UI, broker, speech
companions, maintenance commands and license notices. Deploy the `.exe`; the
release manifest and checksum inventory accompany it for verification.

Portable launches now check for newer releases at startup and every six hours,
including experimental prereleases, and download verified updates. Confirm the
update in Settings to close Swift, replace its executable and reopen with the same
launch options and data directory. Manual checksum verification and replacement
remain available. The updater verifies the source, manifest and executable again
before replacement; failed downloads retain the current application.

Imported audio uses one asynchronous native reader with bounded, backpressured
segments. Transcription selects quiet boundaries near segment limits, carries
remaining PCM forward and reports progress for memory-admitted recordings.
Host-bound ASR source builds enable supported ARM kernels from observed CPU
capabilities; actual-device speed and transcription quality remain unqualified.

Context guidance follows the broker's admitted capacity. The pinned native Prism
**0.1.25** runtime retains its fixed **8,192-token** context; native memory-selected
context requires a separately reviewed runtime release. Publisher serving can
select context from memory. The development defaults remain original Swift PQ2,
four CPU row workers, K4/V4 cache with explicit FP16 recovery, and the standard
adapter at strength 1.3. Publisher rollback is explicit; PTQ1 remains opt-in.

Use serviced Windows 11 ARM64, the compatible Microsoft Visual C++ ARM64 runtime
and at least **15.5 GiB available RAM** before model startup. Model weights,
adapter, inference runtime and speech models remain separate downloads. Preserve
the same user data directory for existing model downloads and conversations.

The release remains unsigned and experimental. Verify downloads against the
published checksums and source identity. Clean-machine launch, live update and
rollback behavior, actual-model startup, full-context quality, sustained
performance and isolation retain their separate acceptance gates in
[the plan](../../PLAN.md). See [Windows releases](../releases.md) for setup.
